# 確認一覧カード

確認一覧・要確認事項の xlsx を読み込み、1件ずつカードで答えて xlsx に書き戻すページ。https://sayakaokamura.github.io/review-card/

xlsx はブラウザの中だけで読み書きし、どこにも送らない。

## AI がブラウザで操作するとき

ダイアログ（alert・confirm）は出さない。知らせは画面上部の `#notice`（role="status"）に出る。

| すること | 操作する要素 |
|---|---|
| xlsx を読み込む | `#pick`（file の input。名前「xlsx ファイルを選ぶ」）にファイルを渡す |
| 前回の続きから始めるか | 読み込んだあと `#notice` に出るボタン。`#restoreYes`（続きから始める）／`#restoreNo`（xlsx に書いてあるとおりで始める） |
| 1件を開く | 左の一覧の `.item`（role="button"。名前は「No.（決定済み／保留／書きかけ／未回答）」）。`#prev`・`#next` で前後へ |
| 一覧を絞る | `#filters` のボタン（すべて／未回答／書きかけ／保留／QAに起票。確認一覧は区分ごと、要確認事項は業務の分・開発の分・資料の食い違い・資料の書き漏れ・確認の分け方ごと） |
| 答える | カードの `[data-kind]` のボタン。`advice` おすすめどおり（おすすめのある問いだけ）／`answer` 回答を書く／`ask` QAに起票（前の名前は「お客様に確認」。その値・列も読む）／`hold` 保留／`none` 不要。もう一度押すと外れる。押しているものは aria-pressed="true" |
| 回答を書く | `answer` を押すと出る `#ans`（必須） |
| 起票する質問の文を直す | `ask` を押すと出る `#qa`（初めは業務向けの問いの文） |
| 備考を書く | `#memo`（どのボタンのときも書ける。必須ではない） |
| 決める | `#decide`（決定して次へ）。ボタンを押していて、`answer` なら `#ans` が埋まっているときだけ押せる。決めたあとは `#redo`（決め直す） |
| xlsx に保存する | `#save`（答えを入れた xlsx を保存）。元のファイル名でダウンロードされる |
| 起票分を出す | `#qaout`（起票分を出力）。「QAに起票」にして決定したものを、QA表の列の並び（No・現行機能・対象・質問・確認の内容・BlueMemeの案・参考資料）で `<機能名>_QA起票.xlsx` にダウンロードする。形は QA表に合わせる（シート「QA一覧」、B 列から、1〜3 行に表題、5 行に見出し、6 行から行。回答・回答者・回答日・ステータスは黄色の空欄） |

ページを離れても「このサイトを離れますか」は出ない。保存していない答えはこのブラウザの控え（localStorage）に残り、同じ xlsx を読み込み直すと `#notice` で戻すかを訊く。xlsx に残すには `#save` で保存する。

## 書き込む列

| | 確認一覧（シート「確認一覧」） | 要確認事項（シート「要確認事項」） |
|---|---|---|
| おすすめどおり | 確認結果「妥当」 | 要約への回答（おすすめの答え） |
| 回答を書く | 確認結果「回答」、回答 | 要約への回答 |
| QAに起票 | 確認結果「QAに起票」、QA起票文 | QAに起票（質問の文） |
| 保留 | 確認結果「保留」 | 検討事項（小問の文）、要約への回答に「→検討事項」 |
| 不要 | 確認結果「不要」 | 不要 |
| 備考 | 備考 | 備考 |

要確認事項は、1件を番号付きの小問（要約）に分け、どの列にも「n.〜」の形で小問の番号を付けて書く。無い列は右の端に足す。前の作りで「業務に確かめる」にした小問の認識合わせの列は、読んだまま残す。
